路由表鋪路，防火牆確定該流量能否通過。
防火牆不是很智慧的東西，他單純判斷合不合規則，通常要手動設定。
## 1. 三種策略的定義與行為

| **策略**     | **行為模式**                       | **對發送端（Client）的表現**                |     |
| ---------- | ------------------------------ | ---------------------------------- | --- |
| **ACCEPT** | **允許通過**。封包被接收並傳遞到下一個階段。       | 正常連線，無延遲。                          |     |
| **DROP**   | **直接丟棄**。防火牆收到封包後直接刪除，不予理會。    | 請求會持續等待直到**連線逾時（Timeout）**。        |     |
| **REJECT** | **明確拒絕**。丟棄封包的同時，回傳一個錯誤訊息給發送端。 | 立即收到「連線被拒（Connection Refused）」的通知。 |     |
## 2. 深入對比：DROP vs. REJECT

這是最常被拿來討論的兩者，它們在不同場景下各有優劣。

### **DROP (丟棄)**

- **隱身效果（Stealth）：** 對方不知道你的伺服器是否存在，或者該連接埠是否被防火牆阻擋。
- **節省資源：** 防火牆不需要額外產生回應封包，對於應對 **DDoS 攻擊**或大規模掃描非常有效。
- **缺點：** 對於合法的連線排錯（Debug）很不友善，因為發送端會一直等，直到幾十秒後才斷線。

### **REJECT (拒絕)**

- **禮貌與規範：** 符合 TCP/IP 協議的精神。它會發送一個 ICMP 錯誤封包（通常是 `port unreachable`）或 TCP RST。
- **快速反應：** 開發者或用戶能立即知道連線失敗，不需要乾等 Timeout。
- **缺點：** 暴露了伺服器的存在。此外，如果遭遇攻擊，防火牆為了回覆大量的 REJECT 封包，反而會消耗自身的頻寬與 CPU 效能。
